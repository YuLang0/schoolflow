# SchoolFlow 제작 프롬프트

아래 내용을 그대로 AI 코딩 도우미에게 주면 지금의 SchoolFlow와 같은 앱을 처음부터 만들 수 있도록 정리한 프롬프트입니다.

---

## 역할과 목표

너는 웹 프론트엔드·백엔드 개발자다. **경기모바일과학고등학교 학생 전용 학교생활 통합관리 웹앱 "SchoolFlow"**를 만든다.
시간표 · 급식 · 학사일정 · 과제 · 시험 · 내신 · 공지를 한곳에서 관리한다.
모든 화면 문구와 오류 메시지는 **자연스러운 한국어**로 쓴다.

## 기술 스택

- Vite + React + TypeScript (strict), 별도 UI 라이브러리 없이 CSS 변수로 직접 스타일링
- 인증·DB: Supabase (`@supabase/supabase-js`, implicit flow)
- 배포: Netlify (GitHub 저장소 연결, push하면 자동 배포)
- 서버 기능: Netlify Functions (나이스 API 중계)
- 테스트: Vitest(jsdom) 단위 테스트 + Playwright 브라우저 테스트
- 라우터 없이 화면 상태(state)로 화면 전환. 인증 링크가 주소의 `#access_token=…`을 쓰므로 해시 라우터를 쓰지 않는다.

## 저장 모드 두 가지

1. **계정 동기화 모드**: 환경변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`가 있으면 사용. 데이터를 Supabase에 계정별로 저장해 어느 기기에서든 로그인하면 같은 데이터가 보인다.
2. **로컬 데모 모드**: 환경변수가 없으면 브라우저 localStorage에만 저장. 비밀번호는 PBKDF2(100,000회, SHA-256)로 해시해서 저장한다.

로그인 화면 아래에 지금 어떤 모드인지 안내 상자를 보여 준다.

## Supabase 스키마

모든 데이터를 테이블 하나에 담는다 (`supabase/schema.sql`, 여러 번 실행해도 안전하게).

```sql
create table if not exists public.schoolflow_items (
  user_id    uuid not null default auth.uid() references auth.users (id) on delete cascade,
  collection text not null check (collection in ('timetable','assignments','exams','events','notices','settings')),
  id         text not null check (char_length(id) between 1 and 100),
  data       jsonb not null check (pg_column_size(data) < 20000),
  updated_at timestamptz not null default now(),
  primary key (user_id, collection, id)
);
```

- RLS를 켜고 select/insert/update/delete 정책 4개 모두 `(select auth.uid()) = user_id`
- `anon` 권한은 모두 회수하고 `authenticated`에만 권한 부여
- 화면에는 먼저 반영하고(낙관적 업데이트) 저장이 실패하면 오류 배너를 띄운 뒤 서버 데이터를 다시 불러온다.

## 계정 기능

- 회원가입(이름·별명, 이메일, 비밀번호): 이메일 인증 메일 발송, 가입 후 "메일함(스팸함 포함) 확인" 안내
- 이미 가입된 이메일이면 Supabase가 `identities: []`인 사용자를 돌려주므로 이를 감지해 안내
- 로그인 실패 시 미인증이면 **인증 메일 다시 보내기** 버튼 (60초 재요청 대기)
- **비밀번호 찾기**: 이메일 입력 → `resetPasswordForEmail(redirectTo: 사이트 주소)` → 메일 링크로 들어오면 **새 비밀번호 설정 화면**
  - `PASSWORD_RECOVERY` 이벤트와, supabase-js가 지우기 전에 미리 읽어 둔 주소의 `type=recovery` 둘 다로 감지
- **설정에서 비밀번호 변경**: 현재 비밀번호를 `signInWithPassword`로 확인한 뒤 `updateUser`
- 비밀번호 규칙: 8~72자, 영문과 숫자 포함, 공백 금지. 같은 비밀번호로는 바꿀 수 없다.
- 비밀번호 칸: 보기/숨기기 버튼, **Caps Lock 경고**, **한글 입력 경고**(한/영 실수 방지)
- 만료된 링크(`error_code=otp_expired`)는 "링크가 만료되었거나 이미 사용되었습니다" 안내 후 비밀번호 찾기 화면으로
- 가입 인증 링크로 돌아오면 "이메일 인증이 완료되어 로그인되었습니다" 안내
- 처리 후 주소창의 토큰 문자열을 지운다.
- Supabase 오류 코드(`invalid_credentials`, `email_not_confirmed`, `same_password`, `weak_password`, `over_email_send_rate_limit`, "after N seconds", 네트워크 오류 등)를 모두 한국어 문장으로 바꾼다.
- 로그아웃하면 다음 로그인은 홈 화면부터 시작한다.

## 학교 고정 정보

- 학교: **경기모바일과학고등학교 (경기도교육청)**로 고정. 학교 검색 화면은 두지 않는다. 나이스 학교 코드는 처음 한 번 학교 이름으로 찾아 기기에 저장한다.
- 교시 시간 고정 (설정에서는 읽기 전용으로 표시하고, 예전에 저장된 다른 시간·백업 파일의 시간은 무시한다):

| 교시 | 시간 |
|---|---|
| 1교시 | 09:10 ~ 10:00 |
| 2교시 | 10:10 ~ 11:00 |
| 3교시 | 11:10 ~ 12:00 |
| 4교시 | 12:10 ~ 13:00 |
| 점심 | 13:00 ~ 13:50 |
| 5교시 | 13:50 ~ 14:40 |
| 6교시 | 14:50 ~ 15:40 |

- 학생은 설정에서 **학년·반만** 고른다.

## 나이스 API 연동

### 서버 중계 (`netlify/functions/neis.mjs`, 주소 `/api/neis`)

- 허용 엔드포인트와 파라미터만 전달: `schoolInfo`, `classInfo`, `hisTimetable`, `mealServiceDietInfo`, `SchoolSchedule`
- 인증키는 Netlify 환경변수 `NEIS_API_KEY`에서 읽어 붙인다. **브라우저에는 절대 노출하지 않는다.**
- 응답 캐시: 학교 정보 하루, 학사일정 6시간, 나머지 30분

**꼭 지킬 것 (실제로 겪은 문제들)**
- Netlify 함수의 두 번째 인자는 환경변수가 아니라 `context`다. 키는 `Netlify.env.get('NEIS_API_KEY')` 또는 `process.env`에서 읽는다. 잘못 읽으면 키 없이 요청되어 **나이스가 5건만** 준다.
- 나이스는 브라우저처럼 보이지 않는 요청을 거절해 HTTP 500을 낸다. `User-Agent` 헤더를 붙인다.
- 오류가 나면 나이스 응답 앞부분을 함수 로그와 오류 메시지에 남긴다. 키는 남기지 않는다.
- `netlify/functions` 폴더에는 함수 파일만 둔다. 테스트 파일(`*.test.mjs`)을 두면 Netlify가 함수로 인식해 **배포가 실패**한다.
- 브라우저 요청에 버전 파라미터(`v=2`)를 붙여 예전에 캐시된 응답을 무효화할 수 있게 한다.
- 서버 중계가 실패하면 브라우저에서 나이스로 직접 요청하는 대체 경로를 둔다. 인증키 없이 최대 5건이고, 화면에 안내를 띄운다. CSP의 `connect-src`에 `https://open.neis.go.kr`을 허용한다.
- 나이스 결과 코드: `INFO-200`은 데이터 없음(빈 배열), `ERROR-290`은 인증키 오류, `INFO-300`/`ERROR-337`은 이용 한도 초과. 모두 한국어 안내로 바꾼다.

### 시간표 (`hisTimetable`)

- **자동 가져오기**
  - 학년·반을 저장하면 그 반의 이번 주(월~금, 주말이면 다음 주) 시간표를 자동으로 채운다.
  - 매주 처음 앱을 열 때 한 번 자동으로 새로 가져온다.
  - 같은 주·같은 반은 다시 요청하지 않는다. 마지막 동기화한 주와 반을 설정에 저장하고, 실패해도 한 접속 중에는 한 번만 시도한다.
  - 자동으로 가져오면 화면 위에 "자동 업데이트: …" 안내를 띄운다.
- 반이 바뀌면 기존 시간표를 통째로 새 반 시간표로 바꾼다. 이때는 변경 표시를 하지 않는다.
- **바뀐 수업 강조**: 같은 반에서 다시 가져올 때 과목이 달라진 칸은 주황색으로 칠하고 이전 과목을 줄 그어 표시한다.
  - 나이스에서 빠진 수업은 "수업 없음"으로 표시한다.
  - 직접 고치면 표시가 지워지고, "변경 표시 지우기" 버튼도 둔다.
- 공휴일이라 나이스에 비어 있는 요일은 기존 내용을 유지한다. 같은 칸에 같은 과목이면 직접 적은 교실·선생님 정보를 유지한다.
- 7교시까지만 반영하고, 8교시 이후는 몇 개를 뺐는지 안내한다.
- 과목명 앞의 `* `, `- ` 같은 표시는 지운다. 예전에 `* 과목`으로 저장된 칸은 변경으로 보지 않는다.
- "지금 다시 가져오기" 버튼도 둔다.

### 급식 (`mealServiceDietInfo`)

- 급식 화면: 월~금 주간표. **PC에서는 다섯 날을 한 줄에**, 좁은 화면에서는 세로 한 줄씩. 이전 주·다음 주 이동, 오늘 강조, 칼로리 표시
- 메뉴 정리
  - `<br/>`로 나누고 끝의 알레르기 번호 `(5.6.13)`, `(5)`, `5.6.13.`을 분리한다.
  - 앞의 `-`, `·`와 끝의 `*`, `.`를 지운다.
- 설정에서 **내 알레르기(1~19번)**를 고르면 해당 메뉴를 ⚠ 빨간 글씨로 강조한다. 알레르기 번호 표시는 켜고 끌 수 있다.
  - 1 난류 · 2 우유 · 3 메밀 · 4 땅콩 · 5 대두 · 6 밀 · 7 고등어 · 8 게 · 9 새우 · 10 돼지고기 · 11 복숭아 · 12 토마토 · 13 아황산류 · 14 호두 · 15 닭고기 · 16 쇠고기 · 17 오징어 · 18 조개류 · 19 잣
- 홈 화면에 "오늘 급식"(중식) 카드. 기기에 3시간 동안 캐시한다.

### 학사일정 (`SchoolSchedule`)

- 매주 반복되는 "토요휴업일"과 **내 학년이 아닌 일정**은 뺀다. 학년 표시 `ONE/TW/THREE_GRADE_EVENT_YN`을 쓰고, 표시가 하나도 없으면 전체 학년 일정으로 본다.
- 휴업일은 휴일로, 이름에 고사·시험·평가가 들어간 일정은 시험으로 분류한다. 수행평가는 시험으로 보지 않는다.
- **달력**: 날짜 칸에 일정 이름 표시(모바일은 점만), 휴일은 빨간 날짜, 토요일은 파란 날짜
- **홈 화면**: 앞으로 60일 학사일정 카드. 여러 날 이어지는 같은 일정은 기간으로 묶는다.
- "다음 시험" D-day는 내가 적은 시험과 학교 시험 기간 중 가까운 것으로 표시한다.

## 화면 구성 (9개 + 급식)

메뉴: 홈 · 시간표 · 급식 · 과제 · 시험 · 달력 · 공지 · 검색 · 설정
PC는 왼쪽 사이드바, 모바일(720px 이하)은 하단 메뉴 8개에 검색은 상단 아이콘으로 둔다.

- **로그인/회원가입/비밀번호 찾기**
- **홈**
  - 날짜와 인사, 지금 상태("지금 3교시 수업 중 · 20분 남음", "쉬는 시간", "점심시간 🍚 · ○분 후 5교시", "오늘 수업 끝")
  - 남은 과제 수, 다음 시험 D-day, 오늘 수업 수
  - 오늘 시간표(지금 교시 강조, 변경 수업 표시), 해야 할 과제, 다가오는 시험, 학사일정, 오늘 급식, 오늘 일정·중요 공지
- **시간표**
  - 월~금 × 7교시 표, 4교시와 5교시 사이에 점심시간 줄
  - 오늘 요일 열은 색칠하고 요일 이름 **위에 "오늘" 표시**, 지금 교시 칸은 테두리 강조
  - 칸을 눌러 과목·교실·선생님 수정
  - "이미지로 저장"과 "지금 다시 가져오기" 버튼
- **급식**: 위 설명대로
- **과제**
  - 진행 중/완료/전체 필터, 마감일순 정렬, D-day(지남은 빨강, 임박은 주황), 중요도 3단계
  - 체크하면 완료일 기록, CSV 내보내기
- **시험**: "시험 일정"과 "내신 계산기" 두 탭
  - 시험 일정: 예정된 시험과 지난 시험, 점수 기록과 평균, CSV
  - 내신 계산기
    - 5등급제/9등급제 선택. 2025년 고1 입학생부터 5등급제이고, 범위를 넘는 등급은 등급제를 바꿀 때 지운다.
    - 1학년 1학기 ~ 3학년 2학기 탭마다 과목·학점·등급 입력
    - 학기 평균, 전체 평균, 반영 학점: 학점 × 등급의 합을 학점 합으로 나눈 가중평균
    - 석차와 수강자 수로 등급 계산. 누적 비율 상한은 9등급제 4·11·23·40·60·77·89·96·100%, 5등급제 10·34·66·90·100%이고 동점자는 고려하지 않는다.
    - 입력이 멈추면 0.7초 뒤 저장하고, 화면을 떠날 때 남은 변경을 바로 저장한다.
- **달력**
  - 월요일 시작 6주 달력. 과제 마감·시험·내 일정·학사일정을 색 점으로 표시
  - 날짜를 누르면 그날 항목 목록과 일정 추가
- **공지**: 학교·학급 공지 직접 기록, 상단 고정, 중요 공지(홈에 표시), 펼쳐 보기
- **검색**: 과제·시험·일정·공지·시간표를 한 번에 검색하고, 결과를 누르면 해당 화면으로 이동
- **설정**
  - 내 정보: 이름, 고정 학교 표시, 학년, 반
  - 비밀번호 변경
  - 화면: 기기 설정·라이트·다크
  - 교시 시간: 읽기 전용
  - 급식 알레르기
  - 알림: 과제·시험 며칠 전부터 알릴지, 수업 5분 전 알림, 테스트 알림. 앱이 열려 있을 때 30초마다 확인하고 같은 알림은 하루 한 번만 보낸다.
  - 백업(JSON 받기·복원, 검증해서 잘못된 값은 버린다), 시간표 CSV, 로그아웃

## 시간표 이미지

- Canvas로 직접 그린다. 외부 라이브러리는 쓰지 않는다.
  - **가로(공유용) 1600×1000**
  - **세로(배경화면) 1080×1920**: 위쪽을 잠금화면 시계 자리로 비워 둔다.
  - **밝게/어둡게**
- 제목은 "2학년 3반 시간표", 부제목은 학교 이름. 점심시간 줄을 넣고, 아래에 사이트 주소를 넣는다.
- 같은 과목은 늘 같은 파스텔 색(과목 이름 해시)으로 칠한다.
- 긴 과목명은 먼저 글자를 조금 줄여 한 줄에 맞춘다. 그래도 넘치면 띄어쓰기에서 두 줄로 나누고, 띄어쓰기가 없으면 반으로 나눈다.
- 이미지 저장 버튼을 두고, 모바일에서 파일 공유가 되면 공유하기 버튼도 둔다.
- 다운로드 파일 이름은 **영문**으로 한다. 일부 브라우저가 한글 파일 이름을 "download"로 바꾼다.
  - 예: `schoolflow-timetable-2-3-portrait.png`, `schoolflow-assignments-날짜.csv`

## 공통 규칙

- 날짜는 항상 기기 현지 날짜 기준 `YYYY-MM-DD`로 다룬다. `toISOString()`은 쓰지 않는다. 한국 시간 오전 9시 전에 하루가 밀린다.
- D-day 계산은 `Date.UTC(년, 월-1, 일)` 차이로 한다. 월을 1 빼는 것을 잊으면 월말에 틀린다.
- 다크 모드는 CSS 변수로 하고, 첫 화면 깜빡임을 막는 `theme-init.js`를 둔다.
- PC에서는 본문을 메뉴 오른쪽 공간 가운데에 놓는다(최대 너비 1100px).
- 모바일에서 가로 스크롤이 생기지 않게 하고, 버튼·입력칸 높이는 44px 이상으로 한다.
- PWA: `manifest.webmanifest`와 SVG 아이콘, 서비스 워커(화면 이동은 네트워크 우선·실패 시 캐시, 정적 파일은 캐시 우선, 외부 요청은 건드리지 않음)
- 보안 헤더(`public/_headers`): X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, CSP(`connect-src`는 self, Supabase, 나이스만)
- CSV는 엑셀 한글 깨짐 방지 BOM을 붙이고 수식 주입(`= + - @`로 시작)을 막는다.

## 테스트 요구사항

- 단위 테스트(현재 60개 수준)
  - 날짜·D-day 경계, 교시 상태(점심 포함)
  - 알림 중복 방지, CSV·백업 검증, 검색, 비밀번호 규칙, 인증 오류 번역, 인증 링크 해석, 로컬 계정(가입·로그인·변경·재설정)
  - 나이스 응답 해석·메뉴 정리·시간표 합치기와 변경 표시, 자동 동기화 조건
  - 학사일정 필터·묶기, 내신 평균·석차 등급, 이미지 줄바꿈
  - 중계 함수(허용 목록, 키 전달, context 인자, 장애 처리)
- 브라우저 테스트(Playwright): 나이스·Supabase는 가짜 서버로 흉내 내고 실제 화면을 눌러 본다. 모바일 390px 폭에서 가로 넘침이 없는지도 확인한다.

## 배포 절차 (사람이 직접 하는 부분)

1. Supabase SQL Editor에서 `supabase/schema.sql` 실행
2. Supabase → Authentication → URL Configuration
   - Site URL: `https://schoolflow-yulang.netlify.app`
   - Redirect URLs: `https://schoolflow-yulang.netlify.app/**` (개발용 `http://localhost:5173/**`)
3. 나이스 교육정보 개방 포털에서 인증키 발급 (활용용도: 프로그램 개발, 신청유형: 개발계정)
4. Netlify 환경변수
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`: Secret 체크 안 함. 브라우저용 공개 값이라 Secret으로 표시하면 배포가 실패한다.
   - `NEIS_API_KEY`: Secret 체크, Production 값만 넣는다.
5. Netlify → Project configuration → Developer settings → Link repository → GitHub `YuLang0/schoolflow` (branch `main`, build `npm run build`, publish `dist`)
6. 환경변수를 바꾼 뒤에는 Deploys → Trigger deploy로 다시 배포한다.
