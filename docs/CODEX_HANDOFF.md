## 붙여 넣을 프롬프트

```text
너는 이 저장소(YuLang0/schoolflow)의 SchoolFlow 웹앱을 이어서 개발한다.
SchoolFlow는 경기모바일과학고등학교 학생 전용 학교생활 관리 웹앱이고, 이미 실제로 배포되어 학생들이 쓰고 있다.
- 사이트: https://schoolflow-yulang.netlify.app
- 저장소: https://github.com/YuLang0/schoolflow (main 브랜치에 push하면 Netlify가 자동 배포)

## 먼저 할 일
1. docs/PROMPT.md를 끝까지 읽어라. 기능, 데이터 구조, 나이스·Supabase 연동, 휴대폰 화면 규칙,
   그리고 "꼭 지킬 것"에 실제로 겪은 버그와 해결법이 정리되어 있다. 이 문서가 현재 앱의 기준이다.
2. README.md와 package.json을 확인하고 `npm install`, `npm test`, `npm run build`를 실행해
   지금 상태가 깨끗한지(테스트 전부 통과, 빌드 성공) 확인한 뒤 결과를 알려 줘.
3. 확인만 하고, 내가 요청하기 전에는 코드를 바꾸지 마라.

## 기술 구성 요약
- Vite + React + TypeScript(strict), 라우터 없이 화면 상태로 전환, CSS 변수로 스타일(다크 모드 포함)
- Supabase: 인증 + 테이블 하나(schoolflow_items, RLS로 본인 데이터만). 스키마는 supabase/schema.sql
- 나이스 API: 브라우저 → /api/neis(Netlify 함수 netlify/functions/neis.mjs) → open.neis.go.kr
  인증키는 Netlify 환경변수 NEIS_API_KEY에만 있고 브라우저에 절대 노출하지 않는다.
- 테스트: Vitest 단위 테스트(src/**/*.test.ts, tests/**/*.test.mjs) + Playwright 브라우저 확인

## 작업 규칙
- 화면 문구, 오류 메시지, 커밋 메시지, 나에게 하는 설명은 모두 한국어로 쓴다.
- 기존 코드의 스타일(주석 밀도, 이름 짓기, 파일 구조)을 따른다.
- 기능을 바꾸면 관련 단위 테스트를 추가하거나 고치고, `npm test`와 `npm run build`가 통과해야 한다.
- 화면을 바꾸면 PC(1280px 이상)와 휴대폰(390×844) 둘 다 실제로 띄워 확인하고, 휴대폰에서 가로 스크롤이 없게 한다.
- 실제 나이스·Supabase에 붙지 못하는 환경이면 가짜 응답으로 테스트하고, 그 사실을 나에게 분명히 말한다.
- 다음은 하지 마라:
  - netlify/functions 폴더에 함수가 아닌 파일(테스트 등)을 두기 → Netlify 배포가 실패한다.
  - .env나 키 값(Supabase 키, 나이스 인증키)을 커밋하거나 코드에 적기
  - Supabase 스키마(collection 종류 등)를 바꾸는 변경. 꼭 필요하면 먼저 나에게 묻고, 실행할 SQL을 따로 알려 줘.
  - 날짜에 toISOString() 쓰기(한국 시간 기준으로 하루가 밀린다)
- 학교(경기모바일과학고등학교)와 교시 시간(1교시 09:10 … 7교시 16:40, 점심 13:00~13:50)은 고정값이다. 바꾸라고 하기 전에는 건드리지 마라.
- main에 push하면 바로 실제 사이트에 배포된다. 작업이 끝나면 테스트·빌드 결과를 보여 주고,
  내가 올리라고 하면 그때 커밋하고 push해라.
- 끝나면 무엇을 바꿨는지, 무엇을 확인했는지, 확인 못 한 것은 무엇인지 짧게 정리해 줘.
```

## 작업을 맡길 때 요령

**1. 한 번에 한 가지씩 요청하기**
- 좋은 예: "급식 화면에 석식이 있으면 중식 아래에 같이 보여 줘"
- 피할 예: "급식이랑 시간표랑 설정 다 좋게 바꿔 줘" (무엇이 바뀌었는지 확인하기 어렵습니다)

**2. 화면 문제는 캡처와 함께 보내기**
- 어느 화면인지, PC인지 휴대폰인지, 기대한 모습과 실제 모습을 같이 적으면 빨리 고칩니다.

**3. 올리기 전에 확인을 요청하기**
- "고친 뒤 테스트랑 빌드 결과 보여 주고, 휴대폰 화면 캡처도 보여 줘. 괜찮으면 내가 올리라고 할게."

**4. 배포 확인**
- push 후 1~2분 뒤 Netlify **Deploys**에서 맨 위가 **Published**인지 봅니다.
- **Failed**면 그 로그를 Codex에 그대로 붙여 넣고 고쳐 달라고 하면 됩니다.
- 사이트에서 Ctrl+Shift+R(휴대폰은 앱을 완전히 닫았다 열기)로 새로고침해 확인합니다.

**5. 문서도 같이 고치게 하기**
- 기능을 추가하거나 바꾸면 "docs/PROMPT.md와 README.md에도 반영해 줘"라고 덧붙이세요.
- 다음에 다른 AI에게 넘길 때도 이 문서만 주면 됩니다.

**6. 사람이 직접 해야 하는 일 (AI가 못 함)**
- Supabase 대시보드 설정(SQL 실행, URL Configuration, 메일 설정)
- Netlify 환경변수 변경 후 **Trigger deploy**
- 나이스 인증키 재발급
- Codex가 이런 단계를 알려 주면 그대로 따라 하면 됩니다.

## 아직 남아 있는 할 일 (참고)
- 학생들에게 퍼뜨리기 전에 **메일 발송 한도 해결**: Supabase 기본 메일은 시간당 몇 통뿐이라, Resend 같은 SMTP 연결이 필요합니다.
- 반 공유 공지·과제(반장이 올리면 반 전체가 보기). 권한 설계와 스키마 변경이 필요한 큰 작업입니다.
- 앱을 닫아도 오는 알림(Web Push)
- 실제 나이스 데이터로 학사일정이 학교 일정과 맞는지 확인
